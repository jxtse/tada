# Harness verification

The new runtime separates deterministic software contracts from real provider integration and analytical correctness. A passing fixture, a non-empty model answer, or process exit code zero is not evidence that all acceptance gates passed.

Independent review and parent verification support G0–G3 within this bounded first-version scope. The parent reran the complete offline suites and checked actual provider requests, observations, immutable states, output rows and cumulative reservations. The completion pass retained earlier failures and did not substitute a model, protocol, SDK revision or framework. The final categorical-index admission guard was verified offline after the recorded live runs; those live transcripts remain unchanged.

The review found and corrected strict raw-tool argument admission before Pi coercion, cancellation across semantic stages, forensic access to stale-checkpoint logs, split-secret Jupyter output redaction, compaction identity pairing, and categorical-index metadata preservation. Live verification also exposed terminal signal ownership and idle interactive Ctrl-C issues; their failing regressions and repaired outcomes were retained. A failed historical session is not retroactively marked successful.

Provider model names are recorded as requested and reported. Some responses use a gateway alias; successful routing does not independently attest to the exact upstream model identity. Reasoning channels are recorded when exposed, with absence represented explicitly. No safety claim is made for unattended untrusted execution.

## Repeatable offline checks

After project dependencies are installed:

```bash
uv run python -m pytest -q
uv run python -m tada_runtime.schemas --check
npm run schemas:check
npm test
npm run build
```

`tests/test_contracts.py` checks the Pydantic boundary and generated schemas. `tests/test_operators.py` uses explicit fake provider transport to exercise operator success and failure contracts. `tests/test_audit.py`, `tests/test_state.py`, and `tests/test_audit_integration.py` check storage, read-only exports, recovery, and failure cleanup. A synthetic Jupyter message fixture tests matching parent IDs and late-output separation; it is explicitly not a live-kernel test.

Schemas are generated by `python -m tada_runtime.schemas`. The TypeScript generator consumes those schema files. TypeScript/schema prechecks cannot express all Pydantic validators, so the Python authority revalidates before execution and state commitment.

## Real verification protocol

Real calls require explicit user authorization for the intended routes and a finite cumulative request ledger. Keep non-sensitive fixtures small, retain the same ledger across retries and sessions, and stop dispatching new requests when its count or deadline is exhausted. Each main, compaction, intent, batch, reduction, and retry is a separate reserved request. Failed and unknown requests consume reservations; do not reset the ledger to make a gate pass.

Use the actual CLI, Pi controller, supervisor, and persistent kernel. Record requested and reported model IDs and the configured protocol. Then verify the following against event traces and exported data:

1. Only `execute_python` is model-visible, tool execution is sequential, and successive cells share a kernel after an ordinary Python exception.
2. Discover categories, materialize string labels, validate row coverage and category references, compute ordinary pandas aggregates, and export a result.
3. Change grouping dimensions without rerunning the same semantic operation.
4. Compact through Pi, retain the pre-compaction request and summary history, and inspect the same registered state afterward.
5. Request a genuinely new semantic dimension and verify that new operator calls occur.
6. Recover from an intentional Python error without losing earlier committed semantic data.
7. Interrupt a long cell, retain partial output, and confirm no replacement kernel or abandoned provider request loses its owner.
8. Close, validate the log and checkpoint, export an offline viewer, and compare its complete artifacts with the actual model-visible truncated observation.
9. Resume only with matching checkpoint/event hashes; identify transient variables that were not registered. Preserve unresolved attempts as unknown without silently retrying them.

A result assertion should inspect output rows, counts, category references, and content. It should not rely on the agent saying that it completed the task.

## Boundaries of the current implementation

- Trusted-local Python is not a certified sandbox. A separate isolation gate remains required for untrusted or unattended jobs.
- Exact reuse is a complete request-identity match, not a semantic-equivalence cache. Fresh replicates must be marked explicitly.
- Registered snapshots preserve supported JSON and common flat-index pandas values. Arbitrary objects, functions, resources, and complete namespace restoration are out of scope. Missing tabular values are represented as JSON null; flatten MultiIndex objects explicitly.
- A state commit is durable before return, but ordinary filesystem and network side effects of a cell are not rolled back.
- Known-secret redaction is tested across typed stream-fragment boundaries, including partial failed streams. Credentialed raw-only transport copies are explicitly opaque-redacted; credential-free copies preserve exact bytes. Logs still contain user data and are not safe for automatic public publication.
- A gateway's reported model alias is recorded as reported evidence. It does not independently prove the exact upstream model identity.
- The small-input generic hierarchy remains separate from the large paper-guided path. Large execution uses one global reducer and explicitly refuses over-capacity input. [Retention documentation](retention.md) describes the implemented planner, fallbacks, engineering parameters and observed validation limits.

## Retention extension validation

The authorized extension preserves the accepted core and historical evidence. The pure numeric and runtime suites test Jeffreys half counts, paired candidates, realized references, retained counts, nonmonotone selection, outer quantiles, balanced partitions, cancellation and both fallbacks. Actual Jupyter tests with mocked HTTP cover Categorization and Joint Tagging, capacity refusal, fixed final vocabulary and immutable typed evidence. Offline viewers revalidate the typed evidence and its nested references.

One actual CLI/Pi/Jupyter call exercised a 12-row pilot/planner/two-mapper/global-reducer path and exact reuse. Its seven provider requests used the same cumulative ledger. This small live task proves functional integration; it does not establish large-N open semantic quality.

Controlled numeric validation used all six appendix populations at N=2,000, 8,000 and 32,000, each with 5,000 fixed-population partitions and all r=5..20. Independent replay checked the stored counts and results. The online planner saw only the pilot. Its selected budget missed the 95% held-out target in two of the six 32K cases, including one below naive r=k. Those failures are retained; no seed or selection rule was changed to improve the report.
